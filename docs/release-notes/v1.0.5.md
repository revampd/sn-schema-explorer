# Release v1.0.5

v1.0.5 adds **zip file import** for schema exports and a significantly improved
**Configuration Data table** — sortable columns, resizable columns, reorderable
instance columns, and a full-width layout that uses the available screen space.

## What's new

### Zip file import

Drop or select a `.zip` file on the landing page to load a schema export without
manually unzipping it first. Supported layouts:

- **Single JSON in zip** — loads directly.
- **Multi-part export in zip** — manifest + part files bundled together are stitched
  inline; no second file-picker prompt.
- **Multiple JSON files with a manifest** — same stitching logic, all inside the zip.

The file input and drag-and-drop zone now accept `.zip` alongside `.json`. Powered
by [JSZip](https://stuk.github.io/jszip/) (bundled into the HTML, no network
request at runtime).

## Improvements

### Configuration Data table

The comparison table has been significantly improved:

- **Sortable columns** — click any column header (Name, instance columns, Status) to
  sort ascending or descending. The active sort column shows ↑ or ↓; inactive columns
  show a dim ⇅.
- **Resizable columns** — drag the right edge of any column header to resize it.
  Useful when property names or values are truncated.
- **Reorderable instance columns** — drag an instance column header left or right to
  change the comparison order. Sort state, filters, and search are preserved across
  reorders. The resize handle blocks accidental drag triggers.
- **Full-width layout** — the table now fills the full available viewport width. The
  title, tabs, search/filter controls, and stat tiles stay at a comfortable reading
  width (max 1200px). The sidebar and inspector grid tracks no longer consume space
  on non-Schema-Map workspaces.

### Background exporter runtime estimate

The comment at the top of `sn-schema-export.bg.js` now reflects v1.0.4 benchmark
data across three instances and explains the two independent cost drivers:

- **Without record counts: 1–3 minutes** — dominated by `sys_dictionary` bulk fetch;
  scales with dictionary row volume (field count), not just table count.
- **With record counts: 2–6 minutes** — one `GlideAggregate` query per table; scales
  linearly with table count and inversely with cluster size.
