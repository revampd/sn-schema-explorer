# Release v1.0.1

This release delivers the features and bug fixes that were planned for the v1.0.1 milestone, plus a pre-release quality pass: guide corrections, new unit tests, and CSDM 5 data-model reference updates.

## What's new

### Dynamic filter builder for Schema Map (#6)

The sidebar's scope checkboxes are replaced by an Airtable-style condition builder. Add as many conditions as you need — they combine with AND logic. Six condition types:

- **Application Scope** — multi-select pill toggle per scope
- **Table Type** — Regular / DB Views / CMDB CI
- **Table Name** — cycles through Starts with / Contains / Is (exact), searches both technical name and label
- **Has Field** — show only tables that carry a specific field name or label
- **Has Edge** — filter by any of the 8 edge types
- **Field Count** — min/max range
- **Is Custom** — tables matching the configured custom prefix list (e.g. `u_`, `x_`)

A badge on the Filter button shows the active condition count. Conditions persist in saved views and survive page reloads. The filter panel and header search bar are hidden when Path Finder is active (Path Finder has its own from/to inputs).

### Path Finder: hop exclusions (#34)

Hub tables (`sys_user`, `cmdb_ci`, `sys_choice`, …) have hundreds of reference edges and tend to appear in almost every path as a cheap intermediate waypoint, producing noisy results. Two exclusion granularities are now available in the Path Finder sidebar:

- **Table exclusion** — type a bare table name (e.g. `sys_user`) to skip that table as a waypoint. The table can still be used as the start or end of a path.
- **Field exclusion** — type in dot-walk notation (e.g. `task.assigned_to`) to block a single reference field while leaving the target table reachable via other fields. The autocomplete switches to field mode once you type a dot, listing reference fields on that table (including inherited ones). Field exclusion chips appear in cyan.

Active exclusions show as removable chips. "Clear all" removes all at once. Exclusions persist across reloads (`localStorage`).

### Machine-readable schema exports (#16)

Five export formats in the Export panel, each at Full schema or Neighbourhood scope:

| Format     | Extension | Description                                                                                                          |
| ---------- | --------- | -------------------------------------------------------------------------------------------------------------------- |
| Markdown   | `.md`     | Tables as `##` headings; field table + references + inheritance                                                      |
| JSON-LD    | `.jsonld` | `owl:Class`, `owl:DatatypeProperty`/`owl:ObjectProperty`, all 6 edge types as typed predicates                       |
| OWL/Turtle | `.ttl`    | Full OWL ontology: `rdfs:subClassOf`, domain/range, M2M/named-rel/CI topology/view predicates                        |
| OpenAPI    | `.yaml`   | OpenAPI 3.0.3: Table API CRUD paths for every table; DB views read-only; `servers:` block when instance URL is known |
| JSON       | `.json`   | Existing raw schema JSON                                                                                             |

The Node.js extractor gains `--format` and `--edge-types` flags. The Background Script supports `json`, `markdown`, and `jsonld`; OWL/Turtle and OpenAPI require the Node extractor or the viewer.

### Custom table and field highlighting (#7)

Tables whose names start with a configured custom prefix (`u_`, `x_`, or any custom list in Settings → Display) are now highlighted with a distinct border colour on the canvas. Custom fields within the inspector are also highlighted. The prefix list is configurable and the highlighting responds immediately when the list changes.

### Inspector: click field row to copy (#4)

Clicking any row in the inspector's field list copies the technical field name to the clipboard and shows a brief toast confirmation. Useful when writing encoded queries, business rules, or ACL conditions.

### Path Finder: encoded-query copy (#3)

Path Finder results now include a second copy row below the dot-walk — the path formatted as a ServiceNow encoded query fragment (`fieldA.fieldB=<value>`). Replace `<value>` with your filter value and paste directly into a GlideRecord query, list filter, or condition builder.

### Diff view: keyboard navigation (#2)

Navigate the diff sidebar table list with `↑`/`↓`, select/deselect with `Enter`, and clear selection with `Escape`. The cursor resets on list rebuild and when leaving diff mode. Input fields are excluded from key interception.

### Diff view: real-time text filter (#1)

Typing in the toolbar search bar while in diff mode now filters the diff sidebar table list in real time. The filter composes with the Added/Removed/Changed category tabs. Switching into diff mode with an active search term applies the filter immediately.

### Hop-depth radial force (#17)

The D3 physics simulation now includes a soft radial force keyed on each node's hop distance from the selected node. Hop-1 neighbours cluster closer to the centre, hop-2/3/4 push outward. The force is gentle (`strength 0.15`) so it guides the layout without overriding link/charge forces. Only active when a node is selected.

### Edge tooltip improvements (#19, #30)

- Inherited reference fields are shown in the hover tooltip (configurable depth, off by default)
- The hop depth slider maximum is now computed dynamically from the currently active edge types and the selected node's reachable neighbourhood — it no longer over-reports a static cap
- Multi-field collapsed edges: label changed from `"Opened by ×6"` to `"Opened by +5"` (first label + overflow count); tooltip uses a bullet list in `Label (field_name)` format

## Bug fixes

- **Re-insertion of orphaned nodes** (#18) — the BFS re-insertion loop could add nodes with no visible connecting edge when a back-edge violated direction constraints. Guarded with a directionality check.
- **Header search bar inactive in diff view** (#26) — the search bar had no effect while Schema Diff was active. Now filters the diff sidebar list in real time (see above).
- **Diff inspector: added-field row colour** (#10) — when a field existed only in the compare schema, the absent-side base cell was incorrectly coloured green. Fixed so only the cell with actual content receives the added/removed colour.

## Infrastructure & quality

- **Single build target** — removed the `lite` / `full` / `setup` variants. One output: `dist/sn_schema_explorer.html` with all features (Path Finder, Schema Diff, Setup Instructions) always included.
- **D3 inlined at build time** — D3 7.9.0 is injected at build time. Zero CDN or runtime network dependencies.
- **GitHub Actions release workflow** — tags trigger a build and publish a GitHub Release with `sn_schema_explorer.html`, `sn-schema-export.bg.js`, and `sn-schema-export.node.standalone.js` attached.
- **Unit + E2E test suite** (#8, #13) — Vitest unit tests for `computeNeighbourhood`, `computeDiff`, `makeEdgeGeom`, `filterOk` (all 7 condition types + AND/OR), and pathfinding (including hop exclusion logic). Playwright E2E tests for inspector, search, and density controls. CI runs both suites on every push/PR to feature, fix, and release branches.
- **CSDM 5 reference modal** — all table names in the ServiceNow Data Model Reference verified against the official ServiceNow australia-branch documentation. Key corrections: Ideation & Strategy domain uses `sn_align_core_product_idea` / `sn_align_core_planning_item`; Service Delivery uses `cmdb_ci_service_auto` with sub-types; `cmdb_ci_service_business` added to Service Consumption.
