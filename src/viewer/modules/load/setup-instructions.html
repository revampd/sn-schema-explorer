A
Option A — Scripts › Background (recommended)
Navigate to System Definition → Scripts - Background (or search "Scripts - Background" in the navigator). Make sure the application picker (top-right) shows Global. Paste the exporter below and click Run script. The script writes the output as a sys_attachment on your own user record and logs the download URL — open it from the result area to grab the JSON file. Tune the CONFIG block at the top if you want record counts (opt-in, adds ~5–15 min) or direct print-to-output instead. Set format to 'markdown' or 'jsonld' to export in those formats directly — OWL/Turtle and OpenAPI are not supported in the Background Script (export as JSON, then convert via Export ▾ in the viewer or use the Node.js extractor with --format=owl / --format=openapi instead). Use edgeTypes to control which relationship types appear in the Markdown or JSON-LD output.

Expected runtime on a typical instance (~6800 tables): 45–90 seconds without record counts.

Background Script UI notes:
  • Application scope picker — must show Global (see warning above)
  • Record for rollback? — leave checked (default). Creates a rollback context so the script can be rolled back via Script Execution History if something goes wrong.
  • Execute in sandbox? — leave unchecked. Sandbox mode prevents data writes — the script needs to save the JSON as a sys_attachment on your user record, so it will fail silently if this is checked.
  • Cancel after 4 hours? — leave checked (default). The script completes in under 2 minutes on most instances.
💡 Record counts are off by default (includeRecordCounts: false in the CONFIG block). Leave it off for the first run — enabling it adds 5–15 minutes to the export time.

B
Option B — Node.js extractor (local machine)
Requires Node.js 18+ and network access to your instance. The extractor is configured via CLI flags (no inline config block). Save the script as sn-schema-export.js and run it with:

node sn-schema-export.js \ --instance=https://your-instance.service-now.com \ --user=admin --password=*** \ --output=schema.json
Uses the standard Table API — no instance-side setup required. Add --include-record-counts for per-table counts (opt-in, slow). Add --page-size=N to override the API page size (default: 1000 rows/request — increase for faster exports on capable instances, decrease if you see HTTP timeouts).

Authentication: use --user + --password for Basic Auth (shown above), or --apikey=<key> for API key auth — the key is sent as the x-sn-apikey request header and does not require a username or password.

Output format: add --format=<fmt> to control the output format (default: json). The output file extension is set automatically when --output is omitted.
--format=json → schema JSON (.json) — viewer-ready, supports streaming --format=markdown → Markdown doc (.md) — one ## block per table, for wikis / LLMs --format=jsonld → JSON-LD (.jsonld)— owl:Class / owl:DatatypeProperty graph --format=owl → OWL/Turtle (.ttl) — standard OWL ontology (Protégé, ROBOT) --format=openapi → OpenAPI YAML (.yaml) — component schemas with typed properties
Use --edge-types=<list> to control which relationship types appear in Markdown, JSON-LD, OWL, and OpenAPI exports (comma-separated; default: all six).
--edge-types=reference,extends,m2m,rel,view,cmdb_rel

Env-var equivalents are supported: SN_INSTANCE, SN_USER, SN_PASSWORD, SN_APIKEY, SN_OUTPUT, SN_PAGE_SIZE, SN_FORMAT, SN_EDGE_TYPES.
