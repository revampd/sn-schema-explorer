ℹ Run one of the scripts below on your ServiceNow instance to generate a schema JSON file, then drop it above.
⚠ Important: switch the application picker (top-right) to Global before running the Background Script. Running inside a scoped app blocks reads on global metadata tables (sys_db_object, sys_dictionary, ...) and the script will return zero rows. The script's pre-flight check catches this and aborts with a clear error.
A
Option A — Scripts › Background (recommended)
Navigate to System Definition → Scripts - Background (or search "Scripts - Background" in the navigator). Make sure the application picker (top-right) shows Global. Paste the exporter below and click Run script. The script writes the output as a sys_attachment on your own user record and logs the download URL — open it from the result area to grab the JSON file. Tune the CONFIG block at the top if you want record counts (opt-in, adds ~5–15 min) or direct print-to-output instead.

Expected runtime on a typical instance (~6800 tables): 45–90 seconds without record counts.
💡 Record counts are off by default (includeRecordCounts: false in the CONFIG block). Leave it off for the first run — enabling it adds 5–15 minutes to the export time.
ServiceNow — Scripts - Background
⚠ Requires the admin role. For non-admin environments use Option B (Node.js extractor) or ask your ServiceNow administrator to run the Background Script on your behalf.
B
Option B — Node.js extractor (local machine)
Requires Node.js 18+ and network access to your instance. The extractor is configured via CLI flags (no inline config block). Save the script as sn-schema-export.js and run it with:

node sn-schema-export.js \ --instance=https://your-instance.service-now.com \ --user=admin --password=*** \ --output=schema.json
Uses the standard Table API — no instance-side setup required. Add --include-record-counts for per-table counts (opt-in, slow). Add --page-size=N to override the API page size (default: 1000 rows/request — increase for faster exports on capable instances, decrease if you see HTTP timeouts).

Authentication: use --user + --password for Basic Auth (shown above), or --apikey=<key> for API key auth — the key is sent as the x-sn-apikey request header and does not require a username or password.

Env-var equivalents are supported: SN_INSTANCE, SN_USER, SN_PASSWORD, SN_APIKEY, SN_OUTPUT, SN_PAGE_SIZE.
